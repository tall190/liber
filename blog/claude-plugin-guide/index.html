내가 만든 AI를 세상에 — Plugin으로 배포하고 마켓에 올리기

AIClaudePlugin자동화배포실무

Skill을 만들고, MCP 서버를 연결했어요. 그런데 팀원에게 “이거 써봐”라고 하려면 어떻게 해야 할까요?

SKILL.md 파일을 보내고, MCP 설정을 공유하고, 훅 설정을 알려줘야 해요. 파일이 세 개, 설정이 두 군데 — 이걸 매번 수동으로 맞추면 금방 지쳐요.

Plugin은 이걸 한 방에 해결하는 방법이에요. Skill, MCP, Hooks, Agents를 하나의 패키지로 묶어서 설치 한 번으로 다 들어오게 해요. 팀에 배포할 수도 있고, Claude 마켓플레이스에 올려서 누구나 쓸 수 있게 할 수도 있어요.

Plugin이 Skill이나 MCP와 다른 점

이 셋을 비슷한 것으로 보는 경우가 많아요. 레이어가 달라요.

Plugin (배포 단위, 컨테이너)
  ├── Skills    Claude가 실행하는 절차적 지식
  ├── MCP 서버  외부 도구와 데이터 연결
  ├── Hooks     이벤트 기반 자동 실행
  └── Agents    특화된 서브에이전트

Skill은 SKILL.md 파일 하나예요. “이렇게 행동해라”는 지침이에요.

MCP는 외부 시스템(GitHub, Slack, DB)과 연결하는 프로토콜이에요.

Plugin은 이것들을 묶어서 배포하는 패키지예요. 플러그인 없이 Skill만 쓸 수도 있고, Skill 없이 MCP만 묶은 플러그인도 있어요.

비유하자면 — Skill은 작업 매뉴얼, MCP는 USB 어댑터, Plugin은 이것들을 담아서 배포하는 앱 패키지예요.

Plugin의 구조

my-plugin/
├── .claude-plugin/
│   └── plugin.json        # 매니페스트 (이름, 버전, 설명)
├── skills/
│   ├── pr-review/
│   │   └── SKILL.md
│   └── deploy-check/
│       └── SKILL.md
├── .mcp.json              # 이 플러그인이 사용하는 MCP 서버
└── hooks/
    └── hooks.json         # 이벤트 핸들러

plugin.json 예시:

{
  "name": "dev-toolkit",
  "description": "PR 리뷰, 배포 체크, GitHub 연동을 묶은 개발팀 툴킷",
  "version": "1.0.0",
  "author": { "name": "Your Team" }
}

Plugin이 활성화되면 그 안의 Skills, MCP 서버, Hooks가 모두 같이 로드돼요. 설치 한 번으로 전부 들어와요.

Skill 하나뿐이라면

Skill이 하나뿐인 Plugin은 구조를 단순하게 할 수 있어요.

simple-plugin/
├── .claude-plugin/
│   └── plugin.json
└── SKILL.md              # skills/ 디렉토리 없이 루트에

이 경우 plugin.json의 name 필드가 Skill 이름으로도 사용돼요.

Plugin vs 일반 Skill — 네임스페이스가 핵심

Plugin이 일반 Skill과 가장 크게 다른 점은 네임스페이스예요.

일반 Skill은 /pr-review처럼 이름 그대로 불러요.

Plugin 안의 Skill은 /dev-toolkit:pr-review처럼 플러그인 이름이 앞에 붙어요.

이게 왜 중요하냐면 — 여러 플러그인에 같은 이름의 Skill이 있어도 충돌이 없어요. 개인 Skill과 팀 Plugin의 Skill이 같은 이름이어도 덮어쓰지 않아요.

로컬에서 만들고 테스트하기

빠르게 시작하기

# 새 플러그인 초기화
claude plugin init my-toolkit
# → ~/.claude/skills/my-toolkit/ 생성

# 로컬 디렉토리로 테스트
claude --plugin-dir ./my-toolkit

# 변경사항 바로 반영 (재시작 불필요)
/reload-plugins

# 배포 전 검증
claude plugin validate

개발 흐름

1. claude plugin init <이름>  →  디렉토리 생성
2. SKILL.md 작성            →  핵심 기능 구현
3. claude --plugin-dir ./   →  로컬에서 테스트
4. /reload-plugins          →  변경사항 적용
5. claude plugin validate   →  배포 전 검증
6. 배포 (팀 공유 또는 마켓플레이스)

배포: 팀에게, 또는 세상에

Plugin을 만들었으면 어떻게 배포할까요? 범위에 따라 세 가지 방법이 있어요.

1. 프로젝트 스코프로 팀 공유

가장 간단한 방법이에요. 플러그인 디렉토리를 git 레포에 커밋하고 settings.json에 등록해요.

// .claude/settings.json
{
  "enabledPlugins": {
    "dev-toolkit@project": true
  }
}

레포를 클론한 팀원은 다음 Claude Code 실행 시 자동으로 플러그인이 로드돼요.

2. 팀 전용 마켓플레이스

여러 프로젝트에서 공통으로 쓰는 플러그인이라면 팀 마켓플레이스를 만들 수 있어요. GitHub 레포 하나를 마켓플레이스로 쓰는 방식이에요.

// settings.json에 팀 마켓플레이스 등록
{
  "extraKnownMarketplaces": {
    "my-team-plugins": {
      "source": { "source": "github", "repo": "myorg/claude-plugins" }
    }
  }
}

등록하면 팀원이 /plugin install <플러그인명>@my-team-plugins으로 설치할 수 있어요.

3. 공개 마켓플레이스 제출

더 많은 사람이 쓰면 좋겠다면 커뮤니티 마켓플레이스에 제출할 수 있어요.

# 로컬 검증
claude plugin validate

# 제출
# → platform.claude.com/plugins/submit

Anthropic 자동화 안전 검사를 통과하면 anthropics/claude-plugins-community 카탈로그에 올라가요. 특정 커밋 SHA로 고정돼서 버전이 보장돼요.

Claude 공식 마켓플레이스 플러그인들

Anthropic이 직접 큐레이션하는 공식 마켓플레이스(claude-plugins-official)에 뭐가 있는지 알아두면 직접 만들지 않아도 돼요.

카테고리플러그인 예시
코드 인텔리전스typescript-lsp, rust-analyzer-lsp, pyright-lsp
외부 연동github, atlassian, slack, figma, vercel
보안security-guidance (코드 작성 중 취약점 자동 리뷰)
개발 워크플로우commit-commands, pr-review-toolkit
출력 스타일explanatory-output-style, learning-output-style

이 중 LSP 플러그인들이 특히 강력해요. TypeScript나 Python을 쓴다면 해당 LSP를 연결하면 Claude가 코드 인텔리전스 정보(타입, 심볼 정의, 참조 등)에 접근할 수 있어요.

Plugin 설치와 스코프 선택

# 설치 (스코프 선택 UI가 나와요)
/plugin install github@claude-plugins-official

설치 시 스코프를 선택할 수 있어요.

스코프범위공유
User내 모든 프로젝트나 혼자
Project이 레포의 모든 협업자팀 전체
Local이 레포에서 나 혼자없음

팀 전체가 써야 한다면 Project 스코프로 설치하고 settings.json을 git에 커밋해요.

ChatGPT GPTs와 어떻게 다른가

가끔 “ChatGPT 플러그인 같은 건가요?”라고 물어보는 경우가 있어요. ChatGPT 플러그인은 2024년에 종료됐고, 지금은 GPTs가 그 자리를 대신해요. 근데 Claude Code Plugin과는 완전히 다른 것이에요.

ChatGPT GPTsClaude Code Plugin
환경웹 브라우저, 대화 인터페이스터미널, 로컬 개발 환경
사용자일반 소비자 포함주로 개발자
핵심대화 패턴 커스터마이징코딩 워크플로우 자동화
코드 실행샌드박스 내 제한적로컬 머신 전체 권한
외부 연동Actions (OpenAPI spec)MCP 서버 (표준 프로토콜)
버전 관리없음Git SHA로 고정

GPTs는 “AI 챗봇을 커스터마이징하는 것”이고, Claude Code Plugin은 “개발 워크플로우를 자동화하는 패키지”예요.

AI 생태계의 Plugin 개념 지형도

“Plugin”이라는 단어를 플랫폼마다 다르게 써요.

플랫폼확장 단위핵심
Claude CodePluginSkills + MCP + Hooks 묶음
ChatGPTGPTsInstructions + Knowledge + Actions
Gemini CLIExtensionClaude Plugin과 유사한 구조
VS Code / JetBrainsExtension/Plugin에디터 자체를 확장하는 코드 패키지
CursorSkillsSKILL.md 표준 (Plugin 없이 Skill만)

IDE 플러그인(VS Code Extension, JetBrains Plugin)은 에디터 자체를 확장하는 완전히 다른 개념이에요. Claude Code Plugin과 이름이 비슷해서 혼동하기 쉬운데, 아예 다른 레이어예요.

그리고 Skill 파일(SKILL.md) 자체는 agentskills.io 오픈 스탠다드를 따르기 때문에 Claude Code 외에 Codex CLI, Gemini CLI, GitHub Copilot에서도 호환돼요. Plugin이라는 포장은 각 플랫폼마다 다르지만, 그 안의 Skill 내용은 이식성이 있어요.

Skill은 내 AI의 행동을 만들고, MCP는 연결을 만들고, Plugin은 그것들을 묶어서 나눌 수 있게 해줘요.

팀의 코드 리뷰 기준, 배포 절차, 사내 시스템 연동 — 이것들을 Plugin 하나에 담아두면, 새로운 팀원이 와도 /plugin install team-toolkit으로 팀의 AI 환경 전체가 세팅돼요.
